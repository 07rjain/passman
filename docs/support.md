# Support and feedback

Use the [Passman support page](https://passman.subdomain.wtf/support) or [GitHub Issues](https://github.com/07rjain/passman/issues) to contact the maintainer about setup questions, reproducible bugs and feedback. Support is best-effort during the experimental beta, with no guaranteed response time. This guide describes the published contact route; it does not establish external inbox monitoring or an operational support SLA.

Check [service status](https://passman.subdomain.wtf/status), the [quickstart](quickstart.md) and [troubleshooting guide](troubleshooting.md) first. Include the operating system, browser where relevant, Passman version, safe error code and steps using synthetic values. GitHub Issues are public: omit secret values, service keys, passwords, approval codes, authorization headers and vault files. Review screenshots and logs before posting.

For a suspected security issue, use [private vulnerability reporting](https://github.com/07rjain/passman/security/advisories/new), following [the security policy](security.md#reporting-vulnerabilities). Do not disclose sensitive exploit details in a public support issue.

Neither support nor account login can recover a lost vault private key or reset its passphrase. Preserve the existing vault and read [key loss and exposure](key-loss.md) before changing local files.
